# DanZero+ 环境评估

## 一、游戏环境架构

### 1.1 掼蛋游戏基本设定

掼蛋是 **4人2队** 的纸牌游戏：

```
        玩家2 (队A)
           │
玩家3 ──── 桌 ────  玩家1
(队B)      │       (队B)
        玩家0 (队A)
```

- **牌数：** 2副扑克 = 108张，每人 27 张
- **目标：** 队内两人尽量比对手先出完所有手牌
- **级别系统：** 从 2 打到 A（共13级）

### 1.2 特殊机制

| 机制 | 说明 |
|------|------|
| **万能牌** | 当前级别的红心牌可替代任何牌 |
| **进贡/还贡** | 上局末游向头游进贡最大的牌 |
| **接风** | 玩家出完牌后由下家获得出牌权 |
| **炸弹** | 4张+同点数、同花顺、火箭等 |

## 二、游戏服务器 `danserver`

预编译 ELF 64-bit 二进制程序，充当掼蛋"裁判"：

```
启动: danserver 100000    # 运行10万局游戏
通信: WebSocket 端口 23456
地址: ws://127.0.0.1:23456/game/clientN
```

职责：
1. 洗牌发牌（每人27张）
2. 管理进贡/还贡流程
3. 确定出牌顺序
4. **生成所有合法出牌组合 (actionList)**
5. 判断牌型合法性和大小
6. 记录出完顺序，计算胜负

### WebSocket 协议

**通知消息** (只看不回):
```json
{"type": "notify", "stage": "beginning", "myPos": 0, "curRank": "5"}
{"type": "notify", "stage": "play", "curPos": 2, "curAction": [...]}
{"type": "notify", "stage": "episodeOver", "order": [2,0,3,1]}
```

**行动消息** (需要回复出牌):
```json
{
  "type": "act", "stage": "play",
  "handCards": ["H3","H5","S7",...],
  "actionList": [["类型","子类型",["H3"]], ...],
  "indexRange": 15
}
```

AI 回复: `{"actIndex": 2}`

## 三、状态编码 (game.py)

### 3.1 状态向量结构

| 特征 | 维度 | 含义 |
|------|------|------|
| my_handcards | 54 | 自己的手牌 |
| universal_card_flag | 12 | 万能牌能力标志 |
| other_handcards | 54 | 其他三家剩余牌 |
| last_action | 54 | 桌面最新出牌 |
| last_teammate_action | 54 | 队友最近出牌 |
| down_played_cards | 54 | 下家历史已打牌 |
| teammate_played_cards | 54 | 队友历史已打牌 |
| up_played_cards | 54 | 上家历史已打牌 |
| down/tm/up_num_left | 28×3 | 各家剩余牌数 (one-hot) |
| self/oppo/cur_rank | 13×3 | 级别信息 |
| **x_batch 总计** | **567** | 含动作的完整状态 |
| **x_no_action 总计** | **516** | 不含动作的纯状态 |

### 3.2 牌面编码

54维向量：4花色×13点数 + 2王，值为张数(0/1/2)

```
索引:  0  1  2 ... 12  13 ... 25  26 ... 51  52   53
牌面: H2 H3 H4 ... HA  S2 ... SA  C2 ... DA  小王 大王
```

### 3.3 万能牌特征 (12 bit)

| Bit | 含义 |
|-----|------|
| 0 | 手上有万能牌 |
| 1 | 能凑出顺子 |
| 2-7 | 能凑出的最大炸弹级别 |
| 8 | 能凑顺子 |
| 9 | 能凑葫芦 |
| 10 | 能凑三带两对 |
| 11 | 能凑对子 |

## 四、奖励函数

```python
rewards = {
    "1100": +3,   # 双上 大胜
    "1010": +2,   # 己方1、3名
    "1001": +1,   # 己方1、4名
    "0110": -1,   # 小败
    "0101": -2,   # 败
    "0011": -3,   # 双上 大败
}
```

A级决赛局额外 ±1 奖励。

## 五、完整数据流

```
danserver 洗牌发牌
    ↓ WebSocket
game.py 接收, prepare() 编码为向量
    ↓ ZMQ
actor.py: DQN 打分 Top-2 → PPO 选1个
    ↓ ZMQ
game.py: 发送 actIndex 给 danserver
    ↓ (重复直到3人出完)
episodeOver → 计算奖励 → GAE → 发送给 Learner
```

## 六、运行评估结果

### 系统配置

| 资源 | 当前 | 训练需求 |
|------|------|---------|
| CPU | EPYC 9354P × 4核 | 160 CPU |
| RAM | 16 GB | 足够 |
| GPU | 无 | 1× GPU |

### 实测数据

| 指标 | 结果 |
|------|------|
| 模型参数量 | PPO 130万 + DQN 134万 = **265万** |
| 模型大小 | ~10 MB (FP32) |
| 单步推理 | **1.16ms** |
| 推理吞吐 | **860 步/秒** |
| 完整一局 | **~1.94s** |
| 峰值内存 | **352 MB** |

| 1 | 0.66ms |
| 5 | 0.97ms |
| 10 | 1.09ms |

| 50 | 1.70ms |
